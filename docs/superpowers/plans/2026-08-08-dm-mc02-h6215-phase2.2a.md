# DM-MC02 + H6215 Phase 2.2a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a USB CDC-triggered, one-shot `+0.2 rad/s` H6215 test that requires `A` then `G`, runs for 1000 ms, holds zero for 200 ms, and always finishes disabled.

**Architecture:** Keep CAN frame encoding, motion policy, and USB byte buffering in separate host-testable modules. `main.c` remains the hardware orchestrator: it converts feedback and CAN health into a safety snapshot, consumes USB commands, executes requested CAN actions, and emits logs. The first hardware session validates `S/A/X` without motion; only a later explicit user `G` starts the positive pulse.

**Tech Stack:** C11 host tests, STM32H723 HAL/FDCAN, ST USB Device CDC, CMake/Ninja, STM32CubeIDE GNU Arm toolchain, STM32CubeProgrammer CLI.

## Global Constraints

- Default state after reset or power-up is disabled; reset must never start motion.
- USB commands are single ASCII bytes, case-insensitive; CR and LF are ignored.
- `A` arms for exactly 10,000 ms and authorizes at most one `G`.
- `G` is the only Phase 2.2a motion trigger; `B` and continuous-speed commands remain unavailable.
- Target speed is fixed at `+0.200 rad/s` for 1000 ms, followed by `0 rad/s` for 200 ms and Disable.
- Speed commands are refreshed every 10 ms while running or holding zero.
- Start limits: fresh feedback within 500 ms, `STATE=DISABLED`, `MODE=3`, `|V|<0.1 rad/s`, both temperatures below 60 C, and CAN free of warning/passive/bus-off.
- Runtime limits: fresh feedback within 100 ms, `STATE=ENABLED`, `|V|<=0.8 rad/s`, both temperatures below 60 C, and CAN free of passive/bus-off.
- `X` always requests zero speed followed by Disable and clears Arm.
- No motor register writes, position commands, torque commands, DM4310 work, or GitHub push are part of this plan.
